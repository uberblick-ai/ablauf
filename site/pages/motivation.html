ablauf / Motivation

Why we built ablauf

Our documents in Uberblick are full of diagrams, and agents write most of them. We started with Mermaid, and the first version of ablauf was a Mermaid subset. We were not happy with how Mermaid renders, so we built a smaller format that draws what the author decided.

What we wanted from Mermaid and didn't get

Mermaid lays a diagram out automatically. That makes it quick to write, and it is also why we could not get the pictures we wanted: the layout engine decides where each node goes and how each edge runs, and a small edit to the text can rearrange the whole picture.

We wanted simpler diagrams that are easier to read, and control over the layout: which column a step sits in, which row it starts, which side an edge leaves and enters.

The author places, the renderer draws

In ablauf the source records those placement decisions on a coarse grid. The renderer sizes the grid and draws the elbows the chosen sides imply. It never moves anything to fix a problem; it reports the problem with its line number, and the author fixes it. That keeps the picture stable: inserting a role moves the rows below it down and leaves everything else where it was.

Agents can do this without seeing the picture. In our trial, five fresh agents given only the one-page primer each wrote the ub-agents loop with no problems left, and five more each added a role to another agent's file. Edges are still spelled like Mermaid's (-->, : label), because agents already know that spelling. Nothing else is Mermaid.

What ablauf is not

ablauf might never be as sophisticated or as complete as Mermaid. It has two kinds today, flows and fan-outs, no automatic layout, and no Mermaid import or export. For our needs it is sufficient so far, and new kinds come when our documents need them. If you need Mermaid's breadth, Mermaid is the better choice.
