How it works with Uberblick.

Uberblick is where a team's documents live, written by people and agents together. A flow in an Uberblick document is an ablauf block, and since Uberblick 0.4.5 it is the only diagram format there: Mermaid blocks were removed in its favour.

A flow in a document

The block is a fenced code block with the language ablauf. This one is from Uberblick's own docs and shows the check its server runs before an agent's edit.

Agents write it, people edit it

An agent writes the block over Uberblick's MCP server like any other Markdown, after reading the one-page format primer. A person edits the same text in the browser. export_markdown gives the document back as a Markdown file with the fence unchanged, so GitHub and any other Markdown tool still show the source.

Because the source places every node, an edit changes only the lines it touches. A reviewer reads the diff of a diagram the way they read the diff of the words around it.

Checking a diagram

render reports every crossing, overlap or unknown name with its line number. An agent fixes the source until the list is empty, so it gets to a clean diagram without looking at the picture. The build script on the overview does exactly that and fails while any problem is left.

Where it is drawn

The docs on uberblick.ai draw their ablauf blocks at build time with this renderer, in the site's own colours. The Uberblick web editor keeps an ablauf block as a code block and shows its source; it does not draw it yet. The Tiptap guide shows how an editor built on Tiptap can draw it above the source.
