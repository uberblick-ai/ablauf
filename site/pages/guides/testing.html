Test your integration

Test the colours and fonts your host supplies. Ablauf exports its text paint contract so your checks need no renderer classes or glyph sampling.

What Ablauf already tests

The package tests deterministic SVG bytes, escaped labels, ids unique across renders with distinct idPrefix values, diagnostics with one-based source line numbers, and text fitting the supplied fonts metrics. It renders every example and the real playground catalogue for both kinds and checks their text paints against the contract. Hosts can focus on their integration.

Give each inline render a distinct idPrefix and surface its diagnostics. A reported source problem still draws; resolve diagnostics before assessing a figure's appearance.

Check your overrides

TOKENS is a readonly tuple of all supported names without the --ab- prefix, in the order of the palette table. Token is its name union and Palette is Record<Token, string>. Keep your host override map complete for each page theme, then install its entries as --ab-* properties. A partial map can mix your theme with the renderer's defaults.

import { TOKENS } from "@uberblick/ablauf";

// Call for each of your host's theme maps before installing its CSS.
function checkOverrides(overrides) {
  const missing = TOKENS.filter(token => !overrides[token]?.trim());
  if (missing.length) throw new Error(`Missing overrides: ${missing.join(", ")}`);
}

Check that installed overrides reach the inline SVG under every combination of page theme and system scheme. Change the page theme without rerendering and repeat the palette check. Set --ab-bg to the actual opaque host canvas behind the transparent SVG, including the canvas inside a shadow root.

Resolve the effective palette

Read a colour-bearing property on a probe inside the rendered inline SVG. Reading a custom property alone can leave an unresolved expression. Pass the same pinned scheme you gave render, or omit it for an automatic SVG. Exported LIGHT and DARK supply effective defaults when host overrides are absent.

import {
  TOKENS, LIGHT, DARK, checkPalette,
  type Palette, type RenderOptions,
} from "@uberblick/ablauf";

function effectivePalette(svg: SVGSVGElement, scheme?: RenderOptions["scheme"]): Palette {
  const view = svg.ownerDocument.defaultView;
  if (!view || !svg.isConnected) throw new Error("Connect the SVG before testing it");
  const dark = scheme ? scheme === "dark"
    : view.matchMedia("(prefers-color-scheme: dark)").matches;
  const defaults = dark ? DARK : LIGHT;
  const palette = {} as Palette;
  const probe = svg.ownerDocument.createElementNS("http://www.w3.org/2000/svg", "rect");
  probe.setAttribute("width", "0");
  probe.setAttribute("height", "0");
  probe.setAttribute("aria-hidden", "true");
  svg.append(probe);
  try {
    for (const token of TOKENS) {
      probe.style.setProperty("fill", `var(--ab-${token}, ${defaults[token]})`);
      palette[token] = view.getComputedStyle(probe).fill;
    }
  } finally {
    probe.remove();
  }
  return palette;
}

function checkDiagram(svg: SVGSVGElement, scheme?: RenderOptions["scheme"]) {
  const result = checkPalette(effectivePalette(svg, scheme));
  const failures = result.pairs.filter(pair => pair.ratio < 4.5);
  if (failures.length) throw new Error(JSON.stringify(failures, null, 2));
  return result.minimum;
}

Pass the actual SVG element to checkDiagram, whether it is in the document or in a shadow root. The probe is its child, so it sees inherited properties in that tree. After inserting a render made with scheme: "dark", call checkDiagram(svg, "dark"). For an automatic render call checkDiagram(svg) after each system scheme change. The example reads only public --ab-* properties; renderer classes and internal unprefixed properties such as --rework are not an integration API.

Test complete host palettes and renders with overrides removed, including a shadow-root fixture if you embed there. The defaults have known minima: DARK is about 4.707; unchanged LIGHT is about 4.396, from rework-toned edge labels on a band (including inline labels). A strict 4.5 test therefore reports LIGHT until you adjust the host palette. Palette correction with visual review is tracked separately in #86.

Read the paint contract

checkPalette(palette) runs without a DOM. It returns { minimum, pairs }. Each pair has ink, ground, optional opacity, unrounded WCAG text contrast ratio, and a host-readable where. It covers both diagram kinds and both fan-out styles: captions, titles/subtitles, panel contents, pills, legend descriptions and samples, ordinary/inline edge labels, and visible diagnostic text. It checks the whole renderer contract regardless of which tones one diagram uses. It does not measure non-text strokes or infer the canvas from the page.

ground lists layers from back to front, starting with bg, the host canvas. For example, ["bg", "band", "agent-bg", "surface"] with opacity: 0.82 means a decision's surface label box over its tone diamond on a band. Opacity multiplies only the last layer's own alpha. The label box also extends beyond the diamond: a separate pair uses ["bg", "band", "surface"]. Gaps repaint the canvas/band, and pills inside panels add a surface over the panel fill.

Layers composite with alpha source-over in gamma-encoded sRGB, as browsers do. For an opaque accumulated ground, each channel is source × alpha + ground × (1 − alpha). After all ground layers, the ink's alpha composites over that ground. Only then are channels linearized for WCAG luminance: c / 12.92 for c ≤ 0.04045, otherwise ((c + 0.055) / 1.055) ** 2.4. Luminance weights are 0.2126, 0.7152, 0.0722, and contrast is (lighter + 0.05) / (darker + 0.05). The minimum is the lowest unrounded ratio.

Accepted colour forms are #rgb, #rgba, #rrggbb, #rrggbbaa, numeric or percentage rgb()/rgba() (comma-separated or space-separated, with optional alpha), color(srgb r g b / a) with numeric or percentage channels, and transparent. Forms are case-insensitive; surrounding whitespace is allowed. Channels and alpha must be finite and in range (RGB numbers 0–255, sRGB numbers and alpha 0–1, percentages 0–100%). bg must be opaque; other colours may have alpha.

Every token, including non-text colours, must have its own string value. Missing keys, invalid syntax, out-of-range values and unsupported forms throw TypeError; none are skipped. Extra object keys are ignored. Named colours, currentColor, var(), HSL, Lab/OKLCH and other colour spaces are unsupported inputs. Browsers normally resolve ordinary CSS colours to RGB on the probe; if yours preserves another colour space, convert it to an accepted sRGB form before calling the checker, matching the host's actual displayed colour. The function never rounds a result into a passing score.

Fonts and CSP

Wait for host fonts to load before measuring them and supply matching families and synchronous fonts width metrics to render. Check that your browser loads those families without substitution. See host font metrics. The package's fit tests rely on the metrics you provide; they cannot verify a host's font loading.

Exercise the inline SVG under your production Content Security Policy. Its embedded style block must be permitted for palette and text rules to apply, and the probe example uses an inline style property. Test the same embedding and style policy you ship, along with any font sources your host needs. Keep the SVG inline for host CSS inheritance; an <img> has a separate document.
